# 3D view: a live, sectioned, exploded technical illustration

A 3D view is a companion page to an example's 2D sheet: the same object, the same `model.mjs`, drawn as an orthographic isometric half-section you can orbit, cut, explode and drive. It is built with `kit/solid3d.mjs` and written as one standalone page by `writePage3d` (kit/page.mjs). The reference is `examples/floor-pump/` (`scene3d.mjs`, `live3d.js`, `build3d.mjs` → `floor-pump-3d.html`).

**The 2D sheet stays the authority.** Dimensions, tolerances, scales, the parts list and the drafting standards live on the sheet. The 3D view shows arrangement and assembly: where the parts sit in depth, how they come apart, what the section looks like in the round. It has one live dimension at most, no scale (NTS) and no parts table.

## 1. When to add one

Add a 3D view when the request says `3d`, or when depth is the explanation: parts that overlap in the section (a gear pair, a crank and its rod, a valve train), an assembly order (exploded), or a hero picture for a page. Don't add one to make a flat mechanism look busier (a pin tumbler, a token-bucket cistern read better as sheets).

## 2. Files and commands

```
examples/<slug>/scene3d.mjs   the solids: pure data from the example's model.mjs/parts.mjs numbers
examples/<slug>/live3d.js     page code: runs the model, poses parts, adds the example's controls
examples/<slug>/build3d.mjs   writePage3d(...) → examples/<slug>/<slug>-3d.html
examples/<slug>/meta.json     "has3d": true, "shot3d": { "view", "cut", "zoom", "look", "t" }
```

```
node examples/<slug>/build3d.mjs
node scripts/check3d.mjs examples/<slug>/<slug>-3d.html         # must print "check3d passed"
node scripts/shot3d.mjs examples/<slug>/<slug>-3d.html --out a.png --view iso --cut 1 [--explode 1]
     [--theme white|blueprint|paper|dark] [--zoom 5 --look x,y,z] [--t 1] [--balloons 0] [--embed]
node scripts/build-all.mjs                                       # builds build.mjs and build3d.mjs
npm run check3d                                                  # check3d on every *-3d.html
```

`shot3d` and `check3d` use SwiftShader (software WebGL), about 0.6 s a frame, so they work anywhere; `--gpu` uses the machine's GPU. Every page supports `?t= ?view=iso|front|side|top ?cut=0|1 ?offset=mm ?explode=0..1 ?zoom=k ?look=x,y,z ?theme= ?balloons=0 ?embed=1 ?check=1 ?selftest=1 ?bench=1 ?dbg=1`. Default theme: white. `?embed=1` hides the bar, frame, title block and hint (an iframe hero); orbit, drag and keys still work.

## 3. The model of a scene

World millimetres: **x = the sheet's u, y = its v, z toward the viewer; the cutting plane is z = 0**, the sheet's section plane, and the half z > 0 is removed. Put the mechanism on z = 0, exactly as the sheet cuts it.

A scene is `{ parts, fluids, centres }`. A **part** has one balloon number, a name, and one or more **closed solids**. Solids have roles:

| Role | Made with | What it is |
|---|---|---|
| solid (default) | any kind | A closed body. Cut faces are capped with the part's hatch |
| `bore` | `S.bore(lathe or extrude)` | A hole inside another solid of the same part. Its far wall shows through the cut |
| `fluid` | `S.fluid(name, lathe or extrude)` | Air, oil, water: accent stipple, density set at run time. It may overlap moving solids (oil round gears): it shows only where no solid is cut |
| `glass` | `role: "glass"`, lathe or extrude | Seen through; capped only where truly cut |
| `decal` | `S.disc(..., { role: "decal", texture })` | A printed face (a dial), drawn on a canvas with the theme's tokens |
| `mouth` | `S.disc(..., { role: "mouth" })` | A dark hole where a bore opens onto a visible face |
| `ink` | `role: "ink"` | A black part (a needle) |

Hatch is the 2D kit's: `S.part(id, name, solids, { mat: "alu", angle: 45 })` uses `K.MATERIALS` and `K.ANGLES`; `hatch: "solid"` blacks in thin walls, tubes and springs; `hatch: "none"` for rods, nuts, screws, balls, ribs (not hatched when cut lengthwise). Adjacent parts take different angles, as on the sheet. Take them from the sheet's `parts.mjs`.

## 4. API

### Specs (pure; Node can import them, so test a scene with `node -e`)

```js
S.lathe(loop, { axis: "y"|"x"|"z" (or "v"|"u"), at: n | [a, b] })   // a K.revolve half-profile [[r, s], …]
S.cylinder({ axis, at, r, from, to })     S.tube({ axis, at, r0, r1, from, to })
S.extrude(shape, { along: "z"|"y"|"x", from, to, holes: [shape…], bevel, conform: { x, r } })
     // along z: shape is [x, y]; along y: [x, z]; along x: [z, y]. A bevelled outline is given inset by the bevel.
S.box(min, max)   S.sphere(c, r)   S.torus(c, R, r, { axis, arc: [a0, a1] })
S.helix({ axis, at, from, to, radius, wire, turns })            // a spring, wire = diameter
S.gear({ teeth, module, along, at: [cx, cy], from, to, bore, phase, pressure })   // involute spur gear
S.gearOutline({ teeth, module, cx, cy, phase })                  // the outline alone, for extrude
S.disc(c, r, { normal: "y"|"x"|"z", role, texture: (ctx, size, tokens) => {} })
S.part(id, name, solids, { mat, angle, hatch, explode, anchor, pivot, layer })
S.bore(solid)      S.fluid(name, solid, { stretch: { from } })
helpers: S.circle(cx, cy, r, n)  S.polygon(n, R, cx, cy, rot)  S.hexagon(af, cx, cy)  S.rrectAt(cx, cy, hx, hy, r)  S.saddle(a0, a1, b0, b1, bc, r)
```

Any solid also takes `hatch`, `layer` (section 5), `own: true` (its own outline against the part's other solids; default is one outline round the whole part), `explode: [dx, dy, dz]` (on top of the part's), `pivot: [x, y, z]` (to turn or scale that solid alone) and `live: "name"` (to find it with `V.solid`).

### Runtime (live3d.js)

```js
const V = S.create({ scene: SC.scene() });
V.set(id, { pos: [x, y, z], rot: [rx, ry, rz] })   // base pose (before explode), rot about the part's pivot
V.solid(id, "name" | index)                       // the THREE.Group of one solid: .rotation / .scale about its pivot
V.reshape(id, "name" | index, { loop | shape … }) // rebuild a solid whose shape changes (seal, bellows)
V.fluid(name, { density: 0..1, wash: 0..1, stretch: mm, offset: [x, y, z], visible })
V.frame([() => pose(a), () => pose(b)])           // the poses whose union the camera frames
V.drag(ids, { axis: [x, y, z], length: mm, start: () => v, move: (v) => {}, end })
V.key("r", fn)    V.test(name, ({ ptr, key, project, draw }) => ({ pass, info }))
V.dim(a, b, { text, off })                        // a live dimension's SVG, for overlay()
V.project([x, y, z]) → [sx, sy]    V.explode    V.cut    V.input()    V.redraw()
V.run({ step(dt, live) → busy, render(live), overlay() → svg, still: seconds, idleAfter })
```

`step` runs the model (subdivide it, the pump uses 480 Hz), as in the 2D `live.js`; the tour is the page's own. `render` sets poses and fluids only. The kit owns the camera, explode, cut, balloons, keys (1–4 views, E explode, C cut, B balloons, S slow), the theme, reduced motion (it shows the tour at `still` seconds) and the WebGL/CDN fallback that links to the 2D sheet.

## 5. The closed-solid rule and its traps

The section works because every solid is **closed**: a back face is only ever seen through the opening the cut made, so the shader paints it as the cut face, hatched where the view ray meets the plane. Break that and the cut lies.

- **Closed and wound outward.** `S.lathe` builds closed, outward-wound bodies from any profile direction; a profile that touches the axis needs one edge on it. `S.extrude` is closed. Open shapes (a tube end, an open torus arc, a helix end) show their inside: keep them small (spring wire) or close them.
- **Parts never overlap.** Two solids of different parts may touch, never interpenetrate. A shared face is fine: the cut face is drawn 0.25 mm in front of its back face (`uCapBias`), so it wins over the neighbour's coincident front face. (Fluids are the exception: they may overlap.)
- **A part that runs through a bore and out behind it needs `layer: 1`.** A cut face is drawn at its back face's depth. A shaft through a gear pocket, a crank through its case or a bolt through a hole ends further back than the bore's far wall, so the bore (and the casting round it) would hide the shaft's cut face. `layer: 1` on the part pulls its cut faces 1 m forward while assembled (nothing in front of the plane survives the cut, so this is safe); exploded, the pull is off. Parts that sit wholly inside a bore (a ball in its valve chamber, a gear in its pocket) need nothing.
- **The cap bias must stay below the thinnest wall.** At 1 mm the 0.9 mm spring wire's back faces beat its own front faces and the whole spring turned black. Keep walls ≥ 0.3 mm or leave the bias.
- **A polygonal hole round a lathe shaft needs clearance.** An extruded hole (a 40-gon) round a 48-segment lathe rod at the same radius fights in moiré stripes. Give fits 0.05 mm (`S.circle(0, 0, 5.05, 48)` for a Ø10 rod), as a real fit has.
- **Never `side: BackSide`.** three.js draws BackSide by flipping the GL front face, which flips `gl_FrontFacing` too, and the shader then discards what it should draw. The kit uses DoubleSide and culls in the shader.
- **Animated volumes need `frustumCulled = false`.** three culls with the rest pose's bounding sphere; a fluid stretched in the vertex shader leaves it and vanishes in close-ups. The kit sets it for fluids; do the same for anything you deform in a shader.
- **Bores and fluids are volumes, not holes.** Without CSG, a passage is a separate solid inside the casting. A view ray through a cut face next to the passage can dip into it behind the plane and show its far wall where the hatch should be. So a bore or fluid fragment is drawn only where its ray crosses the plane **inside its own profile** (lathe: the [r, s] loop; extrude: the outline and [from, to]), tested in the mesh's rest frame, so it stays right when the part explodes or turns. Outlines over 64 points are resampled evenly for the test; an extrude's holes are not part of it.
- **Bores may overlap** (two gear pockets): each is tested against its own outline. In the lens where both apply, the nearer far wall shows, which reads right when they share a floor; otherwise butt them (the floor pump's drill stops at the cross passage's top).
- **Fluids show only where no solid is cut.** A fluid fragment is skipped wherever the id pass found a cut face, so oil can be one block round two gears and appear only in the tooth spaces.
- **Crease lines never draw on a cut face.** A cap drawn at its back face's depth would let edges inside the solid (the joints between a casting's pieces) show through; the line shader checks the id pass and skips cap pixels. Centre lines are exempt, as on a sheet.

## 6. Castings without CSG

Build the casting as touching closed pieces that share the part's hatch and outline, then put its holes in as bores:

1. **Turned bosses** as lathes (the floor pump's boss: socket, O-ring groove and floor in one profile).
2. **Arms, lugs, feet** as extrusions; a bevel stands in for edge fillets (give the outline inset by the bevel).
3. **Where a flat arm meets a round boss**, `conform: { x: 40, r: 40 }` moves the arm's inner face onto the boss cylinder, so the pieces touch without a gap or an overlap.
4. **Passages** as `S.bore(...)` lathes or extrusions, butted end to end; a `mouth` disc where one opens onto a visible face.
5. **Ribs and webs** as their own thin extrusions with `hatch: "none", own: true` (not hatched lengthwise, outlined against the casting).

Pieces of one part may touch. A piece of one part never sits inside another part.

## 7. The cut plane and the explode axes

- **Cut**: z = 0, the sheet's own section. If the sheet cuts somewhere else, transform the scene so its section is z = 0. The camera sits at azimuth 45° (+x, +z), elevation 35.26°, looking at the cut faces; FRONT looks straight at the section and must read like the sheet's main view. `?offset` slides the plane.
- **Explode** along the assembly's own axis, in assembly order, the base fixed: `explode: [0, dy, 0]` for static parts; `{ to: [x, y, z] }` for moving parts (their assembled place depends on the model, the exploded one doesn't). Symmetric pairs (grips, plugs) take a solid-level `explode` outward.
- **Jog a long assembly.** A straight explosion of the floor pump was 1.4 m tall; exploding the rod, piston and handle up a parallel axis 190 mm to the side halved it and made every part readable. Draftsmen do the same with a jogged explosion line.
- Each exploded part keeps its own half-section: the cutting plane travels with the part's explode offset, so exploding toward the viewer (+z) is fine.
- Fluids hide while exploded; balloons follow their parts.

## 8. Balloons and leaders

Every part gets an `anchor`: `cut: [x, y, z]` on its cut face (z = 0), used while the cut is open, and `out: { c, r, axis }`, a surface point pushed from `c` toward the camera by `r` (`axis` "y", "x", "z", "box" or "sphere"), used when it is closed. `solid: k` makes the anchor ride with one solid (an exploded grip). The kit sorts balloons into two tidy columns beside the model, balances them, and reads the id pass at each anchor: a leader to a hidden part is dashed and its dot hollow (a hidden line). Put anchors on wide parts of the cut face, on alternate sides of the axis for parts that crowd one place (the floor pump's 4, 9 and 10 sit on +x).

## 9. Verification loop

1. `node examples/<slug>/build3d.mjs` and `node -e "import('./examples/<slug>/scene3d.mjs').then(s => s.scene())"` (the scene is pure: errors show here first).
2. `node scripts/check3d.mjs examples/<slug>/<slug>-3d.html` → `check3d passed`. It renders a frozen frame with the cut open and checks WebGL started, no fallback, the canvas is not blank (coverage, pixel variance), then runs `?selftest=1`: the kit's tests (view buttons, keys, wheel, orbit) and the page's own `V.test`s. Add one test per page control (drag a part and see the model move).
3. Shots, and **read every PNG**:
   - `--view iso --cut 1` (white, the default theme) — the whole object with balloons;
   - `--view front --cut 1 --zoom 2.5 --look …` — **compare with the 2D section** side by side: same profiles, same hatches and angles, unhatched rods and nuts, bores open, fluid where the sheet stipples it;
   - `--view iso --cut 1 --zoom 5 --look …` — a close-up of the mechanism: caps hatched, outlines clean, no z-fighting;
   - `--view iso --cut 1 --explode 1` — the explosion reads in order, nothing collides, leaders land on parts;
   - one dark or blueprint shot, and `--embed` if the page is a hero.
4. What artefacts mean:

| You see | Cause | Fix |
|---|---|---|
| Hatch across a passage, parts floating on it | the bore is missing or not a closed volume | `S.bore(...)` of a lathe or extrude |
| A band of bore wall beside a passage | (fixed in the kit) bore drawn where its ray dips in behind the plane | keep bores as lathe/extrude so they are tested |
| Moiré stripes on a cut face | two parts' surfaces coincide with different tessellation | 0.05 mm clearance, or the same kind and segments |
| A thin part solid black, or its surface shows hatch | the cap bias exceeds its thickness | thicken it (≥ 0.3 mm) |
| Stray lines through a hatched face | crease lines of internal faces | (fixed in the kit) creases skip cap pixels |
| A shaft or pin has no cut face inside a bore; the bore's wall shows instead | it runs out behind the bore, so its back face is farther | `layer: 1` on that part |
| A bore shows only on part of its outline | (fixed in the kit) outline over the uniform limit | outlines over 64 points are resampled |
| A fluid vanishes in close-ups | culled with the rest-pose bounds | frustumCulled = false (the kit does it for fluids) |
| A whole part shows hatch from outside | the solid is open, or wound inside out | close it; never BackSide |
| Isolated outline pixels in a cap | pinholes between extrusion triangles | (filtered by the kit) |

## 10. Performance budget

The floor pump (21 parts, 37 solids, 7 fluids) is about 92k triangles and 142 draw calls over the id and colour passes, plus one full-screen outline pass: 15–18 ms a frame on an Intel HD 620 at 1600×1000 with the GPU drained, so 55–60 fps. Keep a scene under about 150k triangles, 250 draw calls and 60 parts. Each solid costs a mesh and a line set in each pass; lathes take 48–144 segments by radius; a helix 60 segments a turn. The balloon visibility read-back (one pixel per balloon every third frame) causes the p90 spikes: fine for 30 balloons. SwiftShader takes about 0.6 s a frame, so headless checks use frozen frames (`?t`). `?bench=1` prints the frame time.

## 11. Worked example: the floor pump

`scene3d.mjs` takes the sheet's numbers. The barrel is the sheet's half-profile; the cup seal is the sheet's own function, rebuilt live:

```js
S.part(3, "BARREL TUBE Ø35×1.5", [S.tube({ r0: 16, r1: 17.5, from: M.FLOOR, to: 430 })], {
  hatch: "solid", explode: [0, 112, 0], anchor: { cut: [-16.75, 250, 0], out: { c: [0, 250, 0], r: 17.5, axis: "y" } } }),
S.part(10, "CUP SEAL Ø32", [S.lathe(P.cupLoop(VP, 0), { live: "cup" })], { mat: "rubber", explode: { to: [190, 146, 0] }, … }),
```

The base is a boss lathe, a side arm extruded along z with `conform` onto the boss, a rib, five bores and a mouth. The air is seven fluids, the chamber stretching with the stroke:

```js
S.fluid("chamber", S.lathe([[0, M.FLOOR], [15.97, M.FLOOR], …, [0, VP]]), { stretch: { from: M.FLOOR + 1 } }),
```

`live3d.js` runs `M.advance` exactly as the sheet does, then poses from it:

```js
function pose(xs) { for (const id of MOVING) V.set(id, { pos: [0, M.STROKE * (1 - xs), 0] }); }
V.frame([() => pose(0), () => pose(1)]);               // frame the whole stroke: the zoom never pumps
function render() {
  pose(x);
  V.set(17, { pos: [P.ballU(lift) - P.ballU(0), 0, 0] });                       // the ball lifts
  V.solid(18, "spring").scale.x = (66 - (P.ballU(lift) + M.BALL_D / 2)) / SC.SPRING_LEN;
  V.solid(21, "needle").rotation.y = (P.needleAngle(needle) * Math.PI) / 180;
  V.reshape(10, "cup", { loop: P.cupLoop(SC.REST.VP, fold) });                  // when fold changes
  for (const f of SC.CHAMBER) V.fluid(f, { density: tint(air.p) });
  V.fluid("chamber", { stretch: M.STROKE * (1 - x) });
}
V.drag([13, 14, 15, 16], { axis: [0, -1, 0], length: M.STROKE, start: () => x, move: (v) => (target = v) });
V.run({ step, render, overlay: () => V.dim([140, top, 0], [140, top - travel, 0], { text: `s=${…}` }), still: 9 });
```

## 12. Notes for other mechanisms

- **Gear pump / differential**: tested in the kit's own test scene:

  ```js
  const m = 3, z = 12, r = (m * z) / 2;                 // centres at x = ±r, cut on the gears' mid-plane z = 0
  S.part(1, "BODY", [
    S.extrude(S.rrectAt(0, 0, 60, 34, 6), { along: "z", from: -10, to: 10 }),
    S.bore(S.extrude(S.circle(-r, 0, r + m + 0.1, 72), { along: "z", from: -8, to: 8 })),   // pockets may overlap
    S.bore(S.extrude(S.circle(r, 0, r + m + 0.1, 72), { along: "z", from: -8, to: 8 })),
  ], { mat: "iron", angle: 45, anchor: { cut: [-50, 20, 0] } }),
  S.part(2, "DRIVE GEAR", [S.gear({ teeth: z, module: m, at: [-r, 0], from: -7.9, to: 7.9, bore: 4 })],
    { mat: "steel", angle: 135, pivot: [-r, 0, 0], explode: [0, 0, 60], anchor: { cut: [-r, 10, 0] } }),
  S.part(3, "IDLER GEAR", [S.gear({ teeth: z, module: m, at: [r, 0], from: -7.9, to: 7.9, bore: 4, phase: 180 / z })],
    { mat: "steel", angle: 45, pivot: [r, 0, 0], explode: [0, 0, 60], anchor: { cut: [r, 10, 0] } }),
  S.part(4, "SHAFT", [S.cylinder({ axis: "z", at: [-r, 0], r: 3.95, from: -30, to: 30 })], { layer: 1, explode: [0, 0, 100], anchor: { cut: [-r, 0, 0] } }),
  S.fluid("oil", S.extrude([[-60, -6], [60, -6], [60, 6], [-60, 6]], { along: "z", from: -8, to: 8 })),  // shows only in the gaps
  // live3d.js: V.set(2, { rot: [0, 0, θ] }); V.set(3, { rot: [0, 0, -θ] });  (equal teeth; else scale by the ratio)
  ```

  Gears sit wholly in their pockets (0.1 mm clear of the floor and the tips), so they need no layer; the shaft runs out behind the pocket, so it takes `layer: 1`. The half-pitch `phase` meshes the pair.
- **Four-stroke / Stirling**: the crankshaft is lathes (journals, pins) plus extruded webs on axis z, with a part pivot on the main bearing axis; the connecting rod is an extrusion whose pose is computed from the crank angle (`pos` of the small end, `rot` from atan2). Valves are lathes moved along their stems; springs are helixes scaled about their seat (`pivot` on the seat, `scale` along the axis). The combustion gas is an extrude or lathe fluid stretched with the piston.
- **Springs and bellows** that change length scale about a fixed end (`pivot`); a shape that changes (a seal lip, a diaphragm) is `V.reshape`d only when it changes by more than 0.01 mm.
- **A part that both moves and has bores** (a valve body sliding, a rotor) is fine: bore tests run in the mesh's rest frame.
